game — orientation

Chronicles organize collaborative play into scenes, stories and weeks, with XP requests connecting play to character advancement. HTTP and WebSocket chat are transports over one posting operation and committed scene events.

Persistence and delivery have different guarantees

Post once, render per viewer

sequenceDiagram
  participant C as HTTP or WebSocket adapter
  participant S as scene_chat
  participant DB as Database
  participant L as Channel layer
  participant W as Viewer consumer
  C->>S: can_post then valid PostForm
  S->>DB: scene.add_post
  alt malformed command
    S-->>C: ActionFailed
  else persisted post
    S->>DB: Register on_commit callback
    DB->>L: group_send after commit
    alt layer fails
      S->>S: Log and preserve committed post
    else delivered
      L->>W: Event containing IDs
      W->>W: Recheck access and render for this viewer
    end
  end
  • Shared posting and caller transaction expectations: game/scene_chat.py:1, game/scene_chat.py:62.
  • Per-viewer HTML is never broadcast to another connection: game/consumers.py:9.
  • Delivery failure is logged, not retried durably here: game/scene_chat.py:94.

Approve or deny spending

sequenceDiagram
  participant V as Approval endpoint
  participant A as decide_spending_request
  participant DB as Database
  participant S as Character service
  V->>A: record, character, approver, decision
  A->>DB: Lock request and resolve concrete character
  A->>A: Check read audience and approver scope
  alt already decided
    A-->>V: SpendingAlreadyDecided
  else pending and authorized
    A->>DB: Lock and refresh character
    A->>S: apply or deny
    alt service fails
      S-->>A: Failed result
      A-->>V: SpendingDecisionError and rollback
    else success
      A-->>V: Result and commit
    end
  end
  • Request identity includes the character ID; outsiders see a missing record response: game/spending_approval.py:49.
  • PC self-approval is rejected, with a scoped NPC exception: game/spending_approval.py:21.
  • Refreshing the locked character avoids overwriting another spend deduction: game/spending_approval.py:69.

Data writers

Scene posting persists through scene_chat and scene.add_post (game/scene_chat.py:79); spending decisions mutate game request rows and character state through character services (game/spending_approval.py:73). XP preview temporarily invokes that same spending path and rolls back (game/xp_spend.py:57). Keep external side effects out of that rollback-based preview contract.

Async consumers use Django sync adapters (game/consumers.py:21); authorization and rendering are viewer-specific. The isolated dependency analyzer reports no internal cycles but categorizes absolute game and sibling-app imports outside the package graph; root analysis is authoritative.
