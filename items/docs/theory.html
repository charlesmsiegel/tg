Judge 1

Theory: This package models the physical and magical possessions a World of Darkness character can own or encounter: mundane weapons, and gameline-specific artifacts (Mage Wonders drawing Quintessence, Werewolf Fetishes/Talens bound to spirits, Changeling Treasures/Dross storing Glamour, Mummy relics/vessels channeling Ba, Wraith artifacts spending Pathos, Vampire bloodstones storing blood). Each item tracks who owns it, where it sits, which chronicle it belongs to, and whether a Storyteller has approved it for play.

Instead of: The other coherent reading is a single generic Item model with a properties bag (JSONField or EAV) plus one shared 'magic item' mixin (rank, background cost, charges, resonance) that every gameline composes from, instead of one dedicated Model+Form+View+URL quadruple per item type (~30 item subclasses). The code didn't take that path consistently: most gamelines got their own from-scratch ItemModel subclass with bespoke fields, but Werewolf's Fetish and Talen instead inherit Mage's Wonder class directly (items/models/werewolf/fetish.py:7, items/models/werewolf/talen.py:7) rather than either defining their own fields or factoring a real cross-gameline mixin — a partial, unacknowledged step toward the generic-base alternative that leaves Mage-specific fields (quintessence_max) stapled onto Werewolf items.

Judge 2

Theory: Items models the physical and mystical objects a WoD character can possess, carry, or store at a location: mundane weapons shared by every game line, plus each game line's own catalogue of magic items governed by that line's specific resource economy (Quintessence/Resonance for Mage, Gnosis for Werewolf spirit-items, Pathos/Corpus for Wraith, Ba/Sekhem for Mummy, Glamour for Changeling, Conviction/Faith for Hunter). An item can be jointly owned by several characters and simultaneously located somewhere in the world.

Instead of: The code could have committed to one of two clean theories: (a) a single generic 'magic item' base (rank, background_cost, a spendable resource pool, resonance) that every game line's artifact-like item extends, or (b) each game line's items being fully bespoke with no shared magic-item concept beyond ItemModel. It actually built (a) as Wonder+WonderResonanceRating and proved it works by reusing it for Werewolf's Fetish and Talen (items/models/werewolf/fetish.py:7, items/models/werewolf/talen.py:7) — but then reverted to (b) for Vampire, Wraith, Mummy, Demon, Hunter and Changeling, each of which hand-rolls its own near-identical rank/background_cost/is_cursed/is_unique shape as a flat ItemModel subclass instead of extending Wonder or any shared mixin. The result is neither theory fully, applied inconsistently by game line rather than by any principled rule.

Judge 3

Theory: This package models the physical and magical possessions a World of Darkness character can own or a location can hold - weapons, artifacts, relics, fetishes, talismans, wonders - where each object's mechanical nature is shaped by the specific supernatural metaphysics of its owning tradition (Quintessence and Resonance for Mage, Ba and Hekau for Mummy, Glamour for Changeling, Gnosis and spirit-binding for Werewolf, blood for Vampire, Corpus/Pathos for Wraith). All items share only a thin common contract: a name, an owner, a chronicle, and multi-character/multi-location ownership.

Instead of: The more structurally coherent path was actually built once - items/models/mage/wonder.py defines a genuine reusable 'magic item' abstraction (rank, background_cost, quintessence_max, a resonance-rating through-model) that Werewolf's Fetish and Talen legitimately inherit from Mage's Wonder class rather than duplicating. But the code did not commit to that path system-wide: Vampire, Wraith, Demon, Hunter, Mummy, and Changeling items instead extend ItemModel directly and hand-roll near-identical concepts (power level/rank, background_cost, a free-text 'powers' field, even a second independent resonance-rating through-model in Mummy) from scratch. The likely reason is that each gameline's items were authored independently, prioritizing canon-fidelity for that one game line (Ba costs, Sekhem thresholds, Hekau paths, Glamour affinities) over paying down the abstraction Wonder had already proven, so 'item' ended up meaning 'whatever this gameline's designer wrote,' constrained only by the ItemModel base and django-polymorphic's inheritance machinery.
