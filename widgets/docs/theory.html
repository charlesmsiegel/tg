Theory: The widgets app models recurring dynamic-form interactions as declarative Django fields, widgets, and mixins that emit the client behavior they need. Chained choices, conditional visibility, create-or-select flows, metadata options, point pools, and formsets are exposed through one reusable package API.

Instead of: Feature-specific JavaScript and form logic in each domain app; the package centralizes recurring interactions so domain forms declare configuration rather than reimplement behavior.
