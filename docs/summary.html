This is a Django 5.1 web application for managing World of Darkness tabletop RPG characters, items, and locations across eight game lines (Vampire, Werewolf, Mage, Wraith, Changeling, Demon, Mummy, Hunter). The intended architecture is one shared polymorphic kernel — core.models.Model, extended per-gameline by characters, items, and locations — under a single game.Chronicle/Storyteller-approval workflow, with accounts holding user identity and ST authority, and tg's GAMELINES registry meant to be the single source of truth for which game lines exist.

Nine packages were mapped and graded (chained_select and widgets both cover the same problem — form-widget UI — because chained_select is dead code superseded by widgets, confirmed at the atlas level). A tenth, populate_db, is deliberately codemap-only: it is game-data seed scripts, not application logic.

The independent per-package and repo-level analyses converge on the same story from three different angles — deterministic code-doctor findings, a from-scratch codebase atlas, and a three-judge theory panel — without seeing each other's conclusions: the shared kernel is real but only partially honored. characters and locations mostly follow it; items largely reverted to unprotected per-gameline copies; the XP economy has at least three non-converging implementations; "which gamelines exist" is answered independently in at least three places that have already drifted; and the package meant to be everyone's dependency-free foundation (core) turns out to import upward from a feature app (game), producing a 6-package import cycle invisible from any single package's own atlas.

None of this is speculative — every finding highlighted here was independently confirmed by direct code reading with file:line citations in the linked codemap and health pages, not inferred from patterns alone.

What stands out

  • 6-package import cycle: core.models imports game.Chronicle while game.models imports back from core — the intended dependency-free foundation depends upward on a feature app
  • A 9th gameline (Orpheus) is registered in tg's GAMELINES but has no models/views/urls anywhere — confirmed at repo scope, not local to one package
  • items has little to no login/permission enforcement across 6 of 8 gamelines, contradicting the project's own CLAUDE.md rule that player-related models require auth
  • The XP economy has at least 3 non-converging spend/approval implementations, including one unlocked write racing a select_for_update-protected path (game)
  • 'Which gamelines exist' is answered independently in at least 3-4 places (tg GAMELINES, core.models hardcoded list, per-app URL patterns) that have already drifted out of sync
